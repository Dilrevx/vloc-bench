Introduction

Introducing the Vulnerability Localization Benchmark (VLoc Bench), a two-phase agentic evaluation for measuring a model's ability to identify security vulnerabilities in source code. Given a repository and generic CWE descriptions, models must explore the codebase through sandboxed terminal access and identify which files contain the vulnerability.

Evaluation Metrics

Phase A: File F1

Measures how accurately models identify vulnerable files in a codebase. Harmonic mean of precision (correct files / submitted files) and recall (correct files / all vulnerable files).

F1 = 2 × (precision × recall) / (precision + recall)

Phase B: True Negative Rate

Measures whether models correctly identify that a patched codebase is clean. Tests if models can avoid false positives on fixed code.

TNR = correct clean declarations / total patched repositories

Key Findings

Model Size vs Performance

Repository Size Difficulty

  • → Vulnerability localization remains challenging: Even the best-performing model (GPT-5.5) achieves only 0.229 File F1, indicating significant room for improvement in automated vulnerability detection.
  • → Domain specialization outperforms scale: Purpose-trained 3B models (Antares family) match or exceed 100B+ parameter general-purpose systems, demonstrating that targeted training provides substantial leverage on security tasks.
  • → Repository size dominates difficulty: Performance drops 10× from smallest (<100KB) to largest (10MB+) repositories. Structural complexity, not vulnerability type, is the primary difficulty predictor.
  • → 38% of entries remain unsolved: Nearly two-fifths of vulnerabilities defeat all evaluated systems, representing a structural floor that current approaches cannot breach regardless of model scale.
